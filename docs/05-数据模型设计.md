# 05 数据模型与技术方案（Jessica 产出）

> 子任务 5｜输入需求：P/G/T/L 相关（联动 E/I/U 设计）｜设计人：Jessica｜日期：2026-10-23

## 1. 技术栈建议

- **客户端**：Flutter 跨平台（iOS/Android 双端；O-010 已拍板：**iOS 首发，Android 跟进**）。
- **服务端**：按 MVP 规模选轻量后端（API + 数据库 + 定时任务）。
- **渲染**：墓碑由 SVG/Canvas 模板确定性渲染（P-012：不用 AI 生图）。

## 2. 实体关系模型

```
User 1 ── N Placement（一人多格）
Cell 1 ── 1 Placement（一格一占用，含周期）
Tombstone 1 ── 1 Placement（墓碑当前绑定；UNPLACED 时无绑定）
User 1 ── N Tombstone（墓碑数据归 owner，永存）
Interaction N ── 1 Tombstone（献花/献爱心）
PointsLedger N ── 1 User（灵石流水）
Report N ── 1 Tombstone（举报）
VIP（User 扩展属性，等级/有效期）
Stamina（User 派生属性，懒计算）
```

## 3. 关键实体与字段

| 实体 | 关键字段 | 约束 |
|---|---|---|
| User | id, nickname, points_balance, vip_expiry, stamina_meta | 余额非负；体力派生；VIP 单档用到期时间表达 |
| Cell | x, y, boundary_status | (x,y) 唯一；坐标规则 G-002 |
| Placement | cell_id, tombstone_id, user_id, period_start, period_end, status(EMPTY/OCCUPYING/GRACE/RELEASED) | 一 Cell 仅一个有效 Placement |
| Tombstone | id, owner_id, name, birth_year, death_year, avatar_url, state(PLACED/UNPLACED), privacy(public/private) | 数据不可删除（L-004）；字段对应 T-001 |
| Interaction | id, type(flower/heart), tombstone_id, user_id, points_effect, ts | 幂等键 |
| PointsLedger | type, amount, balance_after, object_id, ts | 只增不改（docs/01 §2） |
| Report | tombstone_id, reason, status, handler, ts | 处理闭环（子任务 6） |

## 4. 并发与一致性

- **占格并发**：同格同时占用 → 事务 + 行锁 + 幂等键 `occupy:{cell_id}:{period}`；失败方收到"格子已被占用"。
- **灵石原子性**：扣减/回馈走单事务 + 余额检查；流水只增（docs/01）。
- **体力懒计算**：读取时按时间差恢复（docs/02 §2.5），不跑定时任务。
- **续费并发**：多人代续费同时触发 → 幂等键 `renew:{placement_id}:{period}`，仅第一笔生效。
- **占格点击兜底（Teddy 评审补充）**：同用户对同格重复点击 → 幂等返回当前状态；格子刚释放瞬间被他人抢占 → 提示"该格刚被他人占用，请另选空格"。

## 5. 到期释放的工程触发

- **懒计算 + 定时兜底**：读取 Placement 状态时懒判断（period_end 已过 → 进入 GRACE；grace_end 已过 → RELEASED）；另设每日定时任务兜底扫描到期数据，保证推送提醒准时。
- **状态变更幂等**：到期判定只触发一次迁移（状态快照 + 唯一迁移键）。
- **数据保留**：RELEASED 只改 Placement/Cell 状态与 Tombstone.state，不触碰墓碑字段。
- **时间精度（Teddy 评审补充）**：period_end / grace_end 按用户时区自然日 00:00 判定，与 docs/03 §4 口径一致，避免秒级边界竞态。

## 6. 网格渲染性能（MVP 级）

- **客户端虚拟化**：只渲染视口内格子（约 20–40 格/屏）；坐标到数据按"区块"分页拉取。
- **区块拉取协议**（评审补全）：按坐标范围 `cells?x0&y0&x1&y1` 返回**完整区块**（无分页游标——网格是二维连续空间，范围即分页）；客户端对区块做 **ETag/坐标指纹缓存**（`(x0,y0,x1,y1,revision)`），平移只拉新边界区块，重复请求命中缓存；乱序无影响（响应自带坐标范围，客户端按坐标归位）。
- **墓碑渲染数据结构**（评审补全）：详情页下发**渲染参数**（`name / born_year / death_year / avatar_url / style_id / text_align`），客户端用模板确定性渲染；**不下发成品图**（保证文字超清、可缩放）。
- **Placement 唯一约束**（评审补全）：DB 部分唯一索引口径为 `(cell_id) WHERE status IN ('OCCUPYING','GRACE')`（Postgres partial unique index）——OCCUPYING/GRACE 均视为"占位中"，RELEASED 可被重新占用。
- **坐标索引与扩展**（评审补全）：当前规模（±128=16384 格）**普通 `(x,y)` 唯一索引即够**；预留按 16×16 区块分桶（`block_key` 列）以备扩展 ±1024+；接口层已按区块查询，扩展时只加索引/分桶，不改协议。
- **缩略图失效**（评审补全）：墓碑**内容变更事件**（头像/样式/文字更新）触发**异步重生成**（MQ 消费，TTL 60s 内生效），网格缓存带 `tombstone_revision`，变更后旧缩略图自动失效。
- **边界规模**：默认 ±128 网格全量 128×128=16384 格（G-003：边界由管理员配置），数据量小（每格少量字段），分片足够。

## 7. 墓碑模板渲染方案

- **模板系统**：SVG 模板（墓碑轮廓/饰纹/字体布局），服务端用模板 + 用户字段确定性渲染出图（PNG），客户端缓存（T-003、P-012）。
- **文字精确**：姓名/年份由模板固定坐标排版；字符长度超出模板 → 字号自动缩放/换行（有明确规则，不允许截断/乱码）。
- **头像**：上传图裁剪为模板头像位（圆形/椭圆），图片走内容安全校验（子任务 6）。
- **字体与溢出细则（Teddy 评审补充）**：中文墓碑固定系统字体栈（PingFang SC / Noto Sans CJK）；姓名建议 ≤ 8 字（待确认）、年份为四位数字；超长按"字号降级 → 换行 → 省略号 + 详情页全文"顺序处理，不允许截断或乱码。

## 8. 隐私权限模型

- 字段 `privacy = public | private`；private 格子的 Tombstone 内容仅 owner 与受邀者可见。
- 受邀机制：owner 生成邀请（链接/邮箱名单），受邀者通过后可见该格墓碑并可互动。
- 游客视角：private 格显示"占位（私密）"，不暴露姓名/年份/头像。
