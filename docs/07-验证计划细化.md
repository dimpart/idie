# 07 验证计划细化（Jessica 产出）

> 子任务 7｜输入需求：V-001 ~ V-007（见 `../design/requirements/08-验证计划与指标.md`）｜设计人：Jessica｜日期：2026-10-23

## 1. 假设—指标映射

| 假设 | 核心指标 | 辅助观察 |
|---|---|---|
| H1 创建动机 | 创建完成率 | 创建各步流失、平均创建时长 |
| H2 网络效应（V-002） | 寻访转化率、人均格子数 | 分享次数、来源坐标分布 |
| H3 回访留存（V-003） | 7 日回访率 | 续费率、纪念日提醒打开率 |
| H4 互动闭环（V-004） | 互动参与率 | 献花/献爱心次数、回馈领取率、回馈后留存 |

## 2. 指标口径精确定义

| 指标 | 分子 / 分母 | 时间窗 | 门槛（暂定） |
|---|---|---|---|
| 创建完成率 | 进入占格流程并成功生成墓碑的用户 ÷ 进入占格流程的用户 | 全程 | ≥ 60% |
| 7 日回访率 | 第 7 天仍回访（自己或他人格子）的用户 ÷ 首日活跃用户 | 7 天 | ≥ 20% |
| 人均格子数 | 有效格子总数 ÷ 注册用户数 | 30 天 | ≥ 1 |
| 寻访转化率 | 通过分享链接到访墓碑的用户 ÷ 收到分享链接的用户 | 全程 | ≥ 30% |
| 互动参与率 | 收到或送出献花/献爱心的用户 ÷ 活跃用户 | 30 天 | ≥ 30% |

- 活跃用户定义：窗口内 ≥ 1 次有效操作（浏览/互动/创建/续费）。
- 校准：门槛为暂定值（V-005），验证期按真实数据调整并记录调整原因。

## 3. 埋点事件清单

`app_open`、`grid_browse`（含平移深度）、`cell_click`、`occupy_start`、`occupy_success`、`tombstone_generate`、`share_sent`、`share_visit`、`flower_send`、`heart_send`、`rebate_claim`、`renew`、`re_place`、`vip_upgrade`、`checkin`、`points_purchase`。

- 埋点规范：统一事件命名（snake_case）、携带 `user_id / ts / 关联对象`；客户端本地缓存 + 批量上报。
- **埋点方案**（评审补全）：核心漏斗事件**前后端双埋**（服务端为权威数据源：`cell_view / occupy_start / occupy_confirm / tombstone_create / revisit / interact_flower / interact_heart / signup / checkin / purchase`；客户端埋 UX 补充：网格平移时长、创建流程各步骤耗时、体力不足触达）；事件表统一 `event: {user_id, ts, name, params}`。
- **验证期配置热更新**（评审补全）：数值（K/F/s/体力/抽查比例）全部走**配置中心**，验证期调整**不发版**（客户端启动时拉配置，重要参数变更 60s 生效）；TestFlight 3 周内允许中途调参，记录每次调参时间戳与效果。
- **统计口径与效度**（评审补全）：30 人样本用于**方向性验证**（非严格统计显著性），门槛按"多数用户达成行为"判定（如 ≥60% 体验用户完成创建、≥1/3 有过互动）；互动参与率 30% 为观察基准，结合深访解释"为什么"；深访 5-8 人覆盖：完成创建者、未完成者、互动活跃者、流失者四类。
- **监控与调参闭环**（评审补全）：经济四项周报由**运营/PM 人工判定**（系统只做阈值告警），调参走配置中心并留档（docs/01 §10 干预优先级）。

## 4. 内测方案

- **渠道**：TestFlight（iOS）/ 内测包（Android，按 O-009、O-010 确认）。
- **样本**：20–50 位真实用户（V-006），来源建议：亲友 + 目标社区（纪念/丧亲互助类社群，待确认）。
- **周期**：建议 2–4 周（含创建期 + 观察期 + 校准期）。
- **回收**：行为数据（埋点）+ 周度访谈（5–8 人）+ 问卷；关键卡点直接询问原因。
- **统计有效性说明**：20–50 样本下，门槛判断为"方向性结论"而非统计显著；≥ 60% 完成率在 n=40 时对应 ≥ 24 人成功，误差可接受；若样本 < 20，结论仅作参考。

## 5. 校准方法

- 验证期第 2 周未门槛中项 → 校准流程：核对口径 → 排查产品卡点/数据埋点 → 调参（O 系列配置）→ 再观察 1 周。
- 校准必须记录：调整了什么、为什么、影响哪些指标。
- **归因局限说明（Teddy 评审补充）**：MVP 内测无 A/B 对照，门槛达成不能单独归因产品；以访谈 + 行为漏斗佐证因果，结论表述为"方向性验证"。
- 校准后仍不达标 → 进入决策规则（§6）。

## 6. 决策规则（逐假设）

| 情形 | 判断 | 动作 |
|---|---|---|
| 核心指标全部达门槛 | 假设验证通过 | 继续 MVP 迭代 / 启动正式版开发 |
| 部分达门槛 | 假设部分成立 | 针对未达项调整设计（明确调整点），进入下一验证周期 |
| 创建完成率 < 40% 且 3 周无改善 | H1 失败 | 产品转向（降低门槛/换形态），冻结投入 |
| 7 日回访 < 10% 且续费 < 30% | H3 失败 | 复盘留存设计（提醒/仪式感），严重则转向 |
| 互动参与率 < 20% 且回馈领取率低 | H4 未成立 | 调整互动机制（回馈额度/入口），仍无效则降级互动范围 |

## 7. 北极星指标（建议）

- **北极星：每周活跃记忆数**（每周有 ≥ 1 次有效互动的墓碑数）——同时反映创建（墓碑存量）、网络效应（被互动）、留存（持续互动）。
- 拆分护栏指标：创建完成率（供给）、互动参与率（需求）、7 日回访率（留存），任一护栏失守即告警。
- **北极星口径（Teddy 评审补充）**："每周活跃记忆数" = 本周内发生 ≥ 1 次有效互动（献花/献爱心/续费/重新放置）的去重墓碑数；埋点事件 `interaction` 关联 tombstone_id 即可聚合。

## 8. 周报与复盘节奏

- 每周固定产出：指标看板（5 指标 + 护栏）、用户访谈纪要、调参记录、下一周实验。
