# 11 数据库设计（Idie · 爱戴 — 服务端数据模型）

> 作者：Toby｜审核：Teddy + Balon｜日期：2026-10-24
> 存储：业务表 SQLite（服务端本地文件 `idie.db`，bot 进程共享读写；后续可平滑迁移 MySQL/PostgreSQL，DDL 兼容标注）；热数据/并发计数器走 Redis（key 规范见 §5）。
> 约定：主键自增 BIGINT；`created_at`/`updated_at` Unix 秒；软删除一律 `deleted_at`；金额/灵石为 INTEGER；坐标 INTEGER。

## 1. 实体关系总览

```
User ──1:N── Placement ──N:1── Cell
 │                │
 ├──1:N── Tombstone ──1:N── Interaction（献花/献爱心）
 ├──1:N── Ledger（灵石流水，只增不改）
 ├──1:N── Checkin（签到）
 ├──1:N── Invite（邀请）
 ├──1:N── Purchase（充值订单）
 └──1:N── Report（举报）──> Tombstone
Cell ──1:N── CaretakerAuth（代续费授权）
Config（键值配置，全局）
```

## 2. 表结构 DDL（SQLite 方言）

### 2.1 user（用户）

```sql
CREATE TABLE IF NOT EXISTS user (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  uid           TEXT    NOT NULL UNIQUE,          -- DIM ID（sender 身份）
  nickname      TEXT,
  avatar_url    TEXT,
  stone_balance INTEGER NOT NULL DEFAULT 0,       -- 灵石余额（原子操作）
  vip_expiry    INTEGER NOT NULL DEFAULT 0,       -- VIP 到期 Unix 秒，0=非 VIP
  invite_code   TEXT    UNIQUE,                   -- 邀请码
  created_at    INTEGER NOT NULL,
  updated_at    INTEGER NOT NULL,
  deleted_at    INTEGER                           -- 注销（匿名化保留，见 §4）
);
CREATE INDEX idx_user_deleted ON user(deleted_at);
```

### 2.2 cell（格子，坐标唯一）

```sql
CREATE TABLE IF NOT EXISTS cell (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  x          INTEGER NOT NULL,
  y          INTEGER NOT NULL,
  status     TEXT    NOT NULL DEFAULT 'EMPTY',    -- EMPTY/OCCUPYING/GRACE/RELEASED
  block_key  TEXT    NOT NULL,                    -- 16×16 区块分桶："x/y >> 4"，预取/缓存分片
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  UNIQUE (x, y)
);
CREATE INDEX idx_cell_block ON cell(block_key, status);
```

### 2.3 placement（占格记录，当前态 + 历史）

```sql
CREATE TABLE IF NOT EXISTS placement (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  cell_id       INTEGER NOT NULL REFERENCES cell(id),
  user_id       INTEGER NOT NULL REFERENCES user(id),
  tombstone_id  INTEGER REFERENCES tombstone(id), -- 可空：未建墓碑的占格
  status        TEXT    NOT NULL,                 -- OCCUPYING/GRACE/RELEASED
  occupy_at     INTEGER NOT NULL,
  expire_at     INTEGER NOT NULL,                 -- 到期（含缓冲期）时间
  grace_until   INTEGER,                          -- 缓冲期截止（释放时间）
  renew_key     TEXT    UNIQUE,                   -- 幂等键 renew:{user}:{cell}:{sn}（可选存）
  created_at    INTEGER NOT NULL,
  updated_at    INTEGER NOT NULL
);
-- 部分唯一索引：同一格子同时最多一条活跃占格
CREATE UNIQUE INDEX ux_placement_active ON placement(cell_id)
  WHERE status IN ('OCCUPYING','GRACE');
CREATE INDEX idx_placement_user ON placement(user_id, status);
CREATE INDEX idx_placement_expire ON placement(status, expire_at);  -- 惰性扫描+定时兜底
```

### 2.4 tombstone（墓碑，数据永存）

```sql
CREATE TABLE IF NOT EXISTS tombstone (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id       INTEGER NOT NULL REFERENCES user(id),
  name          TEXT    NOT NULL,                 -- 姓名 ≤8 字（TBD 默认）
  born_year     INTEGER NOT NULL,
  death_year    INTEGER NOT NULL,
  avatar_url    TEXT,
  style_id      TEXT    NOT NULL,                 -- 墓碑模板 ID
  text_align    TEXT    DEFAULT 'center',
  epitaph       TEXT,                             -- 铭文
  revision      INTEGER NOT NULL DEFAULT 1,       -- 变更版本（MQ 缩略图重生成依据）
  visible       INTEGER NOT NULL DEFAULT 1,       -- 可见性（可隐藏保留）
  epitaph_visible INTEGER NOT NULL DEFAULT 1,
  review_status TEXT    NOT NULL DEFAULT 'CLEAN', -- CLEAN/PENDING/FLAGGED/BANNED
  created_at    INTEGER NOT NULL,
  updated_at    INTEGER NOT NULL,
  deleted_at    INTEGER                           -- 注销匿名化（保留纪念数据，清个人标识）
);
CREATE INDEX idx_tomb_user ON tombstone(user_id);
CREATE INDEX idx_tomb_review ON tombstone(review_status, created_at);
```

### 2.5 interaction（献花/献爱心）

```sql
CREATE TABLE IF NOT EXISTS interaction (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  tombstone_id INTEGER NOT NULL REFERENCES tombstone(id),
  user_id     INTEGER NOT NULL REFERENCES user(id),   -- 献者
  kind        TEXT    NOT NULL,                       -- FLOWER/HEART
  count       INTEGER NOT NULL DEFAULT 1,             -- 献花束数/爱心数
  rebate      INTEGER NOT NULL DEFAULT 0,             -- 本次回馈灵石（即时入账）
  day         TEXT    NOT NULL,                       -- UTC 自然日 YYYY-MM-DD（频率风控）
  created_at  INTEGER NOT NULL,
  updated_at  INTEGER NOT NULL
);
CREATE INDEX idx_interact_tomb_day ON interaction(tombstone_id, day);
CREATE INDEX idx_interact_user ON interaction(user_id, day);
```

### 2.6 ledger（灵石流水，只增不改）

```sql
CREATE TABLE IF NOT EXISTS ledger (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id       INTEGER NOT NULL REFERENCES user(id),
  type          TEXT    NOT NULL,   -- register/checkin/invite/flower_pay/flower_rebate/heart_rebate/purchase/voucher/grant/admin
  amount        INTEGER NOT NULL,   -- 正=收入，负=支出
  balance_after INTEGER NOT NULL,   -- 交易后余额（审计快照）
  ref           TEXT,               -- 关联单据（tomb_id/order_id/invitee_id...）
  sn            INTEGER,            -- 请求 sn（幂等）
  created_at    INTEGER NOT NULL
);
CREATE INDEX idx_ledger_user ON ledger(user_id, id);
CREATE UNIQUE INDEX ux_ledger_idem ON ledger(user_id, type, sn)
  WHERE sn IS NOT NULL;             -- 幂等：同用户同类型同 sn 只入账一次
```

### 2.7 checkin（签到）

```sql
CREATE TABLE IF NOT EXISTS checkin (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id    INTEGER NOT NULL REFERENCES user(id),
  day        TEXT    NOT NULL,      -- UTC 自然日 YYYY-MM-DD
  streak     INTEGER NOT NULL,      -- 连签天数（跨日归零）
  award      INTEGER NOT NULL,
  created_at INTEGER NOT NULL,
  UNIQUE (user_id, day)
);
```

### 2.8 invite（邀请）

```sql
CREATE TABLE IF NOT EXISTS invite (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  inviter_id   INTEGER NOT NULL REFERENCES user(id),
  invitee_id   INTEGER NOT NULL REFERENCES user(id),
  status       TEXT    NOT NULL DEFAULT 'PENDING',  -- PENDING/SETTLED/EXPIRED
  settle_at    INTEGER,                             -- 结算时间（14 天窗口内首次占格）
  created_at   INTEGER NOT NULL,
  UNIQUE (invitee_id)
);
CREATE INDEX idx_invite_inviter ON invite(inviter_id, status);
```

### 2.9 purchase（充值/首充订单）

```sql
CREATE TABLE IF NOT EXISTS purchase (
  id             INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id        INTEGER NOT NULL REFERENCES user(id),
  order_id       TEXT    NOT NULL UNIQUE,            -- IAP 订单号
  package_id     TEXT,                               -- 套餐 ID
  platform       TEXT    NOT NULL,                   -- ios/android
  receipt        TEXT    NOT NULL,                   -- IAP 回执（唯一入账锚）
  amount         INTEGER NOT NULL,                   -- 实付（分）
  stone_delta    INTEGER NOT NULL,
  vip_days       INTEGER NOT NULL DEFAULT 0,
  voucher_id     TEXT,                               -- 首充 6 个月占格券
  status         TEXT    NOT NULL DEFAULT 'VERIFIED',-- VERIFIED/REVERSED
  created_at     INTEGER NOT NULL,
  updated_at     INTEGER NOT NULL
);
CREATE INDEX idx_purchase_user ON purchase(user_id, created_at);
```

### 2.10 caretaker_auth（代续费授权，独立表）

```sql
CREATE TABLE IF NOT EXISTS caretaker_auth (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  cell_id    INTEGER NOT NULL REFERENCES cell(id),
  user_id    INTEGER NOT NULL REFERENCES user(id),   -- 被授权人
  granted_by INTEGER NOT NULL REFERENCES user(id),   -- owner
  created_at INTEGER NOT NULL,
  UNIQUE (cell_id, user_id)
);
-- 每格授权 ≤5 人（应用层约束 + 此唯一索引防重）
```

### 2.11 report（举报）

```sql
CREATE TABLE IF NOT EXISTS report (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  tombstone_id  INTEGER NOT NULL REFERENCES tombstone(id),
  reporter_id   INTEGER NOT NULL REFERENCES user(id),
  reason        TEXT    NOT NULL,
  detail        TEXT,
  status        TEXT    NOT NULL DEFAULT 'PENDING',  -- PENDING/PROCESSING/RESOLVED/REJECTED
  result        TEXT,                                -- 处置：BANNED/OK
  appeal_deadline INTEGER,                           -- 申诉截止（48h）
  created_at    INTEGER NOT NULL,
  updated_at    INTEGER NOT NULL
);
CREATE INDEX idx_report_status ON report(status, created_at);
```

### 2.12 config（配置中心，O/P 参数热更新）

```sql
CREATE TABLE IF NOT EXISTS config (
  key        TEXT PRIMARY KEY,
  value      TEXT NOT NULL,       -- JSON 值
  ver        INTEGER NOT NULL,    -- 配置版本（config_ver）
  updated_at INTEGER NOT NULL
);
```

## 3. 关键约束与索引决策（评审落定）

| 约束 | 实现 | 依据 |
|---|---|---|
| 同格同时仅一条活跃占格 | placement 部分唯一索引 `(cell_id) WHERE status IN ('OCCUPYING','GRACE')` + 条件 UPDATE 双保险 | 占格并发（评审补全） |
| 坐标唯一 | cell(x,y) UNIQUE | 网格定义 |
| 灵石原子性 | Redis CAS 扣减 + ledger 对账；余额快照 balance_after 审计 | 并发安全 |
| 体力/风控 | Redis（见 §5），不入库 | 高频低持久 |
| 到期释放 | 惰性扫描（读时判） + 每日 00:10 定时兜底（用户时区自然日） | docs/03 |
| 流水只增不改 | ledger 无 UPDATE/DELETE 路径 | 审计 |
| 匿名化注销 | user.deleted_at + tombstone 保留纪念数据、清个人标识 | 合规 |

## 4. 生命周期与墓碑数据

- 占格状态机（docs/03）：`OCCUPYING →(到期)→ GRACE(30 天) →(未续费)→ RELEASED`；释放仅 cell.status 变更，tombstone 保留（未展示）。
- 墓碑永存：任何释放/注销不删 tombstone 行；注销仅 `user.deleted_at` + tombstone 个人标识字段置空/匿名。

## 5. Redis Key 规范（Toby 落盘约定）

```
idie:stamina:{user_id}          # 体力当前值（CAS 扣减）
idie:stamina:progress:{user_id} # 恢复进度（last_tick + 8/2 分钟/点）
idie:stone:{user_id}            # 灵石余额（CAS 扣减，权威源；落库对账）
idie:flow:{tomb_id}:{day}:{kind}# 互动频率计数（献花同墓碑≤3 / 献爱心同墓碑≤5 / 全站日≤20 / 爱心日>150 风控）
idie:vip:{user_id}              # VIP 状态缓存（实时判定，过期回落 30）
idie:lock:cell:{cell_id}        # 占格分布式锁
idie:config:ver                 # 配置版本（热更新 60s 生效）
idie:mq:thumb:{tombstone_id}    # 缩略图重生成队列（MQ 异步，60s 生效，revision 比对）
idie:first_charge:{user_id}     # 首充幂等
```

## 6. 数据访问层

- 复用 `libs.database.Database`（AccountDBI/MessageDBI/SessionDBI，DIM 用户/消息存储），业务表在 `idie/services/database/models.py` 独立建模（SQLite 连接池，跨 bot 进程共享文件，WAL 模式）。
- 写路径：业务事务（占格/入账）统一经 service 层事务函数，避免多 bot 并发写冲突；Redis 为权威热数据，DB 为最终一致审计层。
- 迁移：`database/migrations/` 按版本递增（v001 初始建表），启动时自动执行。
