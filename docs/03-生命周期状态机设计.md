# 03 格子生命周期状态机设计（Jessica 产出）

> 子任务 3｜输入需求：L-001 ~ L-007（见 `../design/requirements/04-生命周期与到期策略.md`）｜设计人：Jessica｜日期：2026-10-23
> 数值口径：缓冲期 **30 天（v4.2 定稿，O-004）**；K 为灵石（docs/08 v4.2，K=100,000/年）；状态与规则不依赖具体数值。

## 1. 设计目标与原则

1. **格子是位置、墓碑是数据**（L-007）：格子有生命周期，墓碑数据永久保留（L-004）。
2. **到期不等于失去记忆**：格子可释放，但墓碑不删除、可重新放置（L-003、L-005）。
3. **流程可预期**：到期前、缓冲期、释放、重新放置各环节均有用户可见的提醒与操作入口。
4. **一人多格独立计费**：每个格子独立走生命周期（G-005、L-001）。

## 2. 状态模型

### 2.1 格子状态机（Cell State）

| 状态 | 含义 | 展示 | 可操作 |
|---|---|---|---|
| `EMPTY` | 空置，可被占用 | 空格 | 占用（消耗 K 灵石） |
| `OCCUPYING` | 占用中·展示中（周期内） | 墓碑展示 | 续费、设私密、管理 |
| `GRACE` | 缓冲期（到期未续费，仍展示，L-002） | 墓碑展示 + 到期标识 | 续费（本人才可）、亲友代续费 |
| `RELEASED→EMPTY` | 缓冲期结束未续费，释放回空置 | 空格 | 任何用户可占用 |

### 2.2 墓碑状态机（Tombstone State）

| 状态 | 含义 | 展示 |
|---|---|---|
| `PLACED`（展示中） | 墓碑位于某占用格上（含缓冲期） | 网格中展示，可被献花/献爱心 |
| `UNPLACED`（待放置） | 格子被释放后墓碑卸下，未重新放置 | 不在网格展示，仅"我的-墓碑管理"可见 |

## 3. 状态迁移明细（事件表）

| # | 事件 | 前置 | 迁移 | 副作用 |
|---|---|---|---|---|
| T1 | 占用 `occupy` | 格子 EMPTY、余额 ≥ K | EMPTY → OCCUPYING；墓碑 → PLACED | 扣 K；生成墓碑（或重新放置） |
| T2 | 到期 `expiry` | OCCUPYING 到期日 | OCCUPYING → GRACE | 触发到期提醒（T-n 提前） |
| T3 | 续费 `renew` | GRACE / OCCUPYING | → OCCUPYING（周期 +1 年） | 扣 K；本人或授权亲友操作 |
| T4 | 缓冲期结束未续费 `grace_end` | GRACE 到期 | 格子 → RELEASED→EMPTY；墓碑 → UNPLACED | 墓碑不删除，转入用户墓碑管理 |
| T5 | 重新放置 `re_place` | 格子 EMPTY、墓碑 UNPLACED、余额 ≥ K | 格子 → OCCUPYING；墓碑 → PLACED | 扣 K；恢复展示与互动（L-005、L-006） |
| T6 | 他人占用被释放格子 | 格子 RELEASED→EMPTY | EMPTY → OCCUPYING（他人） | 原墓碑仍 UNPLACED，可另寻空格 |

## 4. 提醒与续费流程

- **到期前提醒**：T-30 / T-7 / T-1 三次提醒（App 内 + 推送，渠道按 O-009 内测口径确认）；时区按用户时区。
- **缓冲期提醒**：进入 GRACE 时提醒"已进入缓冲期，X 天后释放"；缓冲期结束前再提醒一次。
- **亲友代续费**（L-008）：墓碑 owner 可授权亲友名单；授权亲友在 GRACE/OCCUPYING 期可见"代续费"入口并扣自己灵石完成续费；续费后格子周期顺延，owner 收到通知。
- **续费入口**：墓碑详情页"到期状态"区域常驻；到期后墓碑详情页展示剩余时间。
- **时间口径（Teddy 评审补充）**：`period_end` 为到期日 00:00（用户时区）；到期判定、GRACE 结束（grace_end）同样取用户时区 00:00；提醒（T-n）按自然日；释放迁移发生在判定时刻后的首次读取或每日定时任务（幂等键保证只触发一次）。
- **占格并发兜底**（评审补全）：DB 层对 `Placement` 表加**部分唯一索引 `(cell_id, status='OCCUPYING')`**（Postgres 部分索引），格子从 EMPTY→OCCUPYING 用 `UPDATE ... WHERE status='EMPTY'` 条件更新（受影响行数=0 则重试/提示被抢），双保险防并发占格。
- **到期判定实现**（评审补全）：采用**惰性扫描 + 定时兜底**双通道——用户访问/占格/互动时按 `period_end`/`grace_end` 惰性迁移状态（懒计算同 docs/02 §2.5 思路）；每日 00:10 定时任务批量兜底扫描。时区按用户 profile 时区自然日 00:00 计算（`grace_end = period_end + 30 天 + (次日 00:00 对齐)`）。
- **代续费授权**（评审补全）：独立**授权表** `caretaker_auth(user_id, tombstone_id, relation, granted_at)`（≤5 人，不依赖好友系统）；代续费幂等键 `renew:{cell}:{year}:{caretaker}`；续费成功给 owner 发通知（通知 ID 幂等去重，防止重复续费重复通知）。

## 5. 边界与竞争规则

- **重新放置条件**：目标格子必须为 EMPTY；**原格无保留优先权**——原格子若仍空置可用回（L-005），若已被他人占用则另寻空格（公开竞争，不做占位保留，避免格子被锁死）。
- **缓冲期内墓碑仍展示、仍可互动**（不影响祭奠连续性）。
- **释放后墓碑不可互动**（非展示中，I-002 联动）：互动入口隐藏，详情页显示"该墓碑暂未展示"。
- **数据安全**：T4 释放只解除格子绑定，墓碑数据（姓名/年份/头像）原样保留（L-004）。
- **释放后网格一致性（Teddy 评审补充）**：T4 迁移后网格接口立即返回该格 EMPTY，客户端按需刷新即可看到空格；owner 端墓碑同步为 UNPLACED，并通过 App 内通知 + 推送（一次）告知"格子已释放、墓碑已保留，可重新放置"。

## 6. 待放置墓碑的恢复引导

- UNPLACED 墓碑在"我的-墓碑管理"置顶展示，标注"未展示"状态。
- 引导文案："该墓碑暂未放置，选择空格即可恢复展示与祭奠"；点击直接进入"选格→放置"流程。
- 每次打开 App 时若存在 UNPLACED 墓碑，首页提供轻量提示（不强制）。
- **主动触达节奏（Teddy 评审补充）**：UNPLACED 超过 7 天未放置 → App 内提示；超过 30 天 → 推送提醒一次（可关闭）；此后不再主动触达（避免对哀伤情绪的过度打扰）。
