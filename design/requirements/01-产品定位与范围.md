## 需求清单

| ID | 需求 | 状态 | 备注 |
|---|---|---|---|
| P-001 | 产品名：Idie（爱戴），用于纪念过去的人 | 已确认 | 用户原话："开发一个产品，用于纪念过去的人" |
| P-002 | 产品形态：独立 App | 已确认 | 非小程序 / 非网页优先 |
| P-003 | 纪念对象：任何人都可以（用户可为任意逝者创建墓碑） | 已确认 | 不限定亲属关系 |
| P-004 | 一句话定位：以坐标网格承载的"数字墓园"——任何人都能为所爱之人占用一个格子，生成一块墓碑（数据永久保存），供所有人漫步、寻访、献花与分享 | 已确认 | 含互动（献花） |
| P-005 | 当前阶段："先验证再定"，MVP 先验证核心假设再决定投入 | 已确认 | 与验证计划联动（08） |
| P-006 | 可见性：默认公开，用户可将自己的格子设为仅受邀可见（私密） | 已确认 | 公开带来集体仪式感 |
| P-007 | 设计原则：极简创建（三步生成墓碑）、记忆永久（数据不删除，占用可续费）、克制安静、公开的集体仪式感与可选隐私并存 | 已确认 | |
| P-008 | 红线一：不做电子祭品付费、打赏、广告（增值付费也不采用该形态） | 已确认 | 不可打破 |
| P-009 | 红线二：不做 AI 数字人 / AI 记忆整理（后置探索） | 已确认 | 伦理风险高 |
| P-010 | 红线三：不做公共社区 / 信息流 | 已确认 | 无差异化且增审核负担 |
| P-011 | 红线四：不做家族树 / 家谱 | 已确认 | |
| P-012 | 红线五：墓碑文字不用 AI 生图，用确定性模板渲染（代码绘制 + 精确文字）；头像才使用用户上传图 | 已确认 | 墓碑文字不能出错 |

## 范围边界

- **本期做**：网格浏览、格子占用、墓碑生成、可见性控制、积分占用、互动（献花/献爱心）、体力与 VIP、审核与安全、墓碑管理。
- **暂不做**：AI 记忆/数字人、电子祭品/打赏/广告、家族树/家谱、公共社区信息流、3D/VR 重型体验。
- 详细清单见子任务设计（`../docs/`）逐项展开。
