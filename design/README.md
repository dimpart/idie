# Idie（爱戴）· 设计文档目录

> 本项目产品设计双角色工作流：
> - **Teddy（项目经理）**：理解并归档需求（本目录 `requirements/`）、拆解子任务、派发与评审（`tasks.md`）。
> - **Jessica（产品经理）**：按子任务产出详细设计（`../docs/`），每份设计必须逐条覆盖对应需求 ID。
> - 评审规则：每个子任务完成后，Teddy 对照需求清单检查；不符合则指出问题让 Jessica 重做，通过后才进入下一个子任务。

## 目录结构

```
design/
├── README.md                    # 本索引（工作流、目录说明）
├── tasks.md                     # 子任务分解与评审状态（Teddy 维护）
├── 评审纪要-2026-10-24.md       # 需求评审会纪要（8 模块通过 + 工程决策）
└── requirements/                # 需求归档（源头 Truth，Teddy 维护）
    ├── 01-产品定位与范围.md
    ├── 02-网格与占用.md
    ├── 03-墓碑与内容治理.md
    ├── 04-生命周期与到期策略.md
    ├── 05-积分经济系统.md
    ├── 06-互动与体力系统.md
    ├── 07-交互体验.md
    ├── 08-验证计划与指标.md
    └── 09-待确认参数清单.md
```

> 目录约定：`design/`（需求归档，即本目录）· `docs/`（开发者文档）。
> Jessica 的详细设计存放于 `../docs/`，不在本目录内。

## 红线（所有设计不可打破）

1. 不做电子祭品付费 / 打赏 / 广告；
2. 不做 AI 数字人 / AI 记忆整理（后置）；
3. 不做公共社区 / 信息流；
4. 不做家族树 / 家谱；
5. 墓碑文字不用 AI 生图，必须模板确定性渲染（头像可用用户上传图）。
